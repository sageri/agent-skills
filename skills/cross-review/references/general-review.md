# 通用任务双审（门E·产物门）

非代码交付物（翻译、调研报告、PPT 等）从需求到交付的轻流程；定点门审已有通用产物时也读本文件（门E 清单与送审要求）。门机制（外审者、送审包、结果格式、裁决、2 轮上限、降级链）照 SKILL.md「审核门」一节。

```
疑问问完（基准＝用户本次要求）→ 主代理制作 → 门E → 裁决汇总＋盲区披露
```

疑问规则同 SKILL.md 阶段1。无制作前确认门；大件（长报告、多页 PPT）需要先定方向时，先对大纲过一次门E（清单同下，产物＝大纲）。

## 门E 自审清单

送审前逐条过，结果写进 `review-e.md`（代替门A–D 的代码向清单）：

1. 对照用户要求逐条：每条要求都能指到产物的哪一部分，无遗漏、无多出
2. 事实准确：数字、日期、专名、引用可核；调研类结论有来源
3. 完整一致：术语统一、格式合用途
4. 可追溯：内容取舍追溯到用户要求或写明假设

## 送审包

「需求摘要」以用户本次要求原文代入。任务特有审点——翻译→忠实/漏译/术语一致，调研→来源可信/覆盖面，PPT→结构/要点覆盖——按本次任务在包内声明。

产物一律文本化：PPT→逐页标题＋正文＋备注，xlsx→各 sheet 表格化，报告/翻译→全文内联。视觉/排版属**文本审盲区**：外审不覆盖，主代理自审＋用户验收兜底。

## 落盘与结束

只建本任务目录的 `review-e.md`（自审结果、送审包、结果原文、逐条裁决、usage；任务目录取法见 SKILL.md「落盘与恢复」），不建三件套；产物落用户指定位置。

**完成判据**：门E走完，已交付裁决汇总＋一行盲区披露（如「视觉/排版未经外审」）。
